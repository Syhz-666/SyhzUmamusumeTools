# SyhzUmamusumeTools

为《闪耀！优俊少女》国服制作的本地 Electron 应用。按马娘记录 G1～G3 奖杯，根据未获得奖杯安排三年赛程，导出后在游戏内手动预约。

**直接使用：** 双击 `release/SyhzUmamusumeTools-1.0.2-x64.exe`。Windows x64 便携版，无需安装 Node.js，图片与资料均可离线使用。

## 使用方法

1. 从左侧选择马娘。可搜索国服名字和常见别名，衣装不会列为不同角色。
2. 在「奖杯陈列室」点击奖杯，点亮或取消已获得状态；误操作后可点击提示中的「撤销」。通过 GⅠ／GⅡ／GⅢ、名称、获取状态和适性筛选。默认按游戏陈列顺序排列；点击「展开陈列室」可隐藏两侧栏，显示更多奖杯。
3. 在右侧选择育成剧本和目标路线。不同衣装仅影响目标，奖杯进度按马娘共享。各马娘、目标路线、剧本分别保存预约方案。
4. 按本次继承结果修改草地、泥地和距离适性。有可选或随机目标时，按游戏实际目标选择分支。
5. 可在缺失奖杯下点击「＋目标」，再「预览补杯建议」。不选目标时，尝试全部适性 B 以上的未获得奖杯。预览会列出新增赛事、已在赛程中的目标及未能安排的原因，确认后才加入方案。
6. 在「赛事预约」切换初级／经典级／高级年，点击「＋」手动添加赛事。已预约回合可替换或取消；橙色固定目标可查看条件。可导出完整三年的文字或 PNG 图片，在游戏内照表设置。

**预约不会点亮奖杯。** 比赛获胜后请手动记录。这是本地规划工具，不读取游戏数据，也不控制游戏。

## 数据和排程规则

- 资料快照：**2026-11-02**。87 位马娘、155 座奖杯（G1 35 / G2 44 / G3 76）、216 个举办日期、149 条目标路线，394 张本地图片。
- 六剧本：URA、青春杯、巅峰杯、闪耀舞台、荣耀女神杯、凯旋门计划。
- 固定比赛不能被普通预约覆盖；粉丝数、累计成绩、支持者点数等达成期限不会锁住回合。
- 青春杯、演出、女神杯年末赛按回合后事件显示；巅峰杯替换角色目标，凯旋门替换为共通目标并限制海外远征与结束后的日期。
- 自动建议保留当前预约，默认避开经典／高级年 7～8 月暑期集训、避免新增连续三回合参赛。手动预约允许低适性、集训或连续参赛，并显示相关提醒。
- 优先考虑可用日期少的目标，再考虑赛事等级和日期；每个目标奖杯最多建议一次。它是启发式排程，不保证在单次育成中获得所有目标或达到最优收益。
- 参赛粉丝数仅显示门槛，实际育成条件、比赛结果及随机事件仍需在游戏中核对。数据快照不会自动联网更新。

详细资料来源、特殊目标修正与可复现整理方法见 [DATA-SOURCES.md](DATA-SOURCES.md)。

## 保存与备份

进度自动保存在固定路径 `%APPDATA%/SyhzUmamusumeTools/collection-v1.json`。应用内「数据与备份」显示实际路径；更改 EXE 名称或移动源码不会改变存档位置。首次启动自动迁移旧版 `%APPDATA%/优俊补杯助手` 或 `%APPDATA%/syhz-trophy-planner` 中的存档，保留原文件，已有新版存档优先。

默认自动持久化：应用在显示可编辑界面前读取现有存档，每次修改自动保存，重新打开直接恢复，无需导入。写入临时文件后刷新到磁盘、原子替换并回读校验，成功后才显示「已保存」。退出前由窗口与主进程握手，等待最后一次保存完成。

主文件无法读取时自动尝试 `.bak` 并修复主文件；两份均无法读取时显示错误和「重新读取」，停止普通保存，不以空进度覆盖原文件。JSON 导入用于主动恢复外部备份或迁移电脑，不是正常重启的必要步骤。`persistence.log` 仅在本地记录读写结果和数量，不记录奖杯明细，也不会上传。

「导出全部数据备份」包含所有角色的奖杯、预约、适性和目标分支。「从 JSON 恢复」先校验内容并展示概况，确认后替换。文件版本、角色、赛事、日期、目标冲突和适性非法时会拒绝导入。

便携程序的位置不影响用户存档位置；迁移电脑前请导出 JSON。测试使用独立测试目录，不修改正常用户存档。只有同时传入 `--qa` 和 `SYHZ_QA_DIR` 才启用交互测试目录，并在页眉和标题明确显示「测试存档」；正常双击始终打开正式存档。

## 从源码运行

需要 Windows x64、Node.js 22.12 以上（推荐 24）。

```powershell
npm ci
npm run build
npm start
```

`npm run dev` 会先构建再启动 Electron，修改代码后重新运行即可。首次安装若尚未下载 Electron 运行时，可运行 `node node_modules/electron/install.js`。

```powershell
npm run check   # TypeScript 检查
npm test        # 排程与存档回归测试
npm run test:persistence # 真实 Electron：已有36项 → 点亮后立即退出 → 重启自动恢复37项
npm run smoke   # Electron 离线渲染及桌面桥接检查
npm run pack    # 生成 Windows x64 portable EXE
```

`npm run pack` 使用 `node_modules/electron/dist` 的运行时；首次打包需要网络下载构建组件。构建产物在 `release`，本地便携版未进行代码签名。

目录：`app/src` 为 React 界面及独立排程逻辑，`main.cjs`／`preload.cjs` 为隔离的 Electron 主进程和桥接，`store.cjs` 为存档校验与原子保存，`app/public` 为离线资料和资源，`tests` 为回归测试，`scripts` 为资料整理及图标生成程序。

## 界面

绿色页眉、圆角游戏面板、三列木质奖杯架、聚光灯与金／灰奖杯；窗口宽度充分利用，可展开为自适应多列陈列室。预约页采用每年四列六行的半月格与粉色「预约中」标记。右侧辅助栏保留规划、目标备忘和导出。

这是非官方辅助工具，角色与赛事图像归各权利方所有。

本地 `release` 仅保留最新版本；新版本验证通过后清理旧版与打包中间文件。GitHub 已发布的历史版本单独管理。
